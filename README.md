# gpu-worker

Однократная настройка нового Windows-ПК как GPU-воркера (доступ по Tailscale + SSH).

## Одна команда

PowerShell **от администратора**:

```powershell
irm https://raw.githubusercontent.com/azama2t/gpu-worker/main/setup_once.ps1 | iex
```

Что делает: ставит Tailscale (один раз откроется вход), включает OpenSSH Server с автозапуском и правилом брандмауэра, добавляет публичный ключ главного ПК, выключает сон, ставит план «Высокая производительность». В конце печатает IP в Tailscale, имя ПК и пользователя — их нужно прислать оператору.

Дальше всё (окружение, данные, раннер обучения как скрытая задача) разворачивается по SSH с главного ПК. Секретов в репозитории нет: только публичный ключ.

## Дополнительные шаги (по умолчанию выключены)

Параметры через `irm | iex` не передаются — запускайте как блок:

```powershell
& ([scriptblock]::Create((irm https://raw.githubusercontent.com/azama2t/gpu-worker/main/setup_once.ps1))) -OnlyExtras -Root E:\proj -Layout -CleanupTask
```

| Ключ | Что делает |
|---|---|
| `-Root E:\proj` | корень проекта (по умолчанию `D:\worker`, если есть D:, иначе `C:\worker`) |
| `-Layout` | создаёт раскладку папок (ниже) |
| `-CleanupTask` | ежечасная задача «GPU Worker Cleanup» по правилам ниже; журнал `<корень>\logs\cleanup.log` |
| `-StopFreeGB 40`, `-TmpHours 24` | порог свободного места для флага `STOP_DISK` и срок жизни `tmp` |
| `-SetTdr` / `-UndoTdr` | TdrDelay=60 и TdrDdiDelay=60 / откат к сохранённым значениям; нужна перезагрузка |
| `-OnlyExtras` | не трогать Tailscale/SSH/питание, выполнить только выбранные шаги |

## Хранение и чистка

Правило: **у каждого файла есть место, владелец и срок жизни; всё остальное удаляет программа.** Реальные случаи, из-за которых это написано: staged-копии завершённых заданий заполнили диск воркера целиком (~90 ГБ, GPU простаивала), а входные пакеты «по одному на запрос» и артефакты CI без срока переполнили чужой сервер, и он упал.

Раскладка — один корень на самом большом диске, ничего вне него:

```
<диск>:\<проект>\
  runner\           раннер, окружение, локальная очередь jobs.json, state\
  jobs\<id>\in\     входы задания (ссылка/hardlink на cache, не копия)
  jobs\<id>\ckpt\   только last + best
  jobs\<id>\out\    экспорт, result.json, лог задания
  outbox\           готовое к доставке + sha256 + manifest
  cache\            переиспользуемое (кадры, стартовые веса), с потолком
  logs\             логи (ротация 50 МБ x 3)
  tmp\              всё временное
```

- Раннер выставляет `TMP`/`TEMP` в `<корень>\tmp\<id>`, а `TORCH_HOME`, `HF_HOME`, `PIP_CACHE_DIR` и подобные — в `cache\`. Ничего в `%TEMP%`, в корне диска и в профиле пользователя.
- Задание удаляется **сразу после доставки**, подтверждённой sha256 на стороне получателя: квитанция `jobs\<id>\DELIVERED.json` вида `{"files": {"out/model.onnx": "<sha256>"}}`. Нет квитанции — не удалять.
- Папку с файлом `LEASED` (живое задание) чистка не трогает никогда.
- Свободного места меньше порога — флаг `<корень>\STOP_DISK`: раннер не берёт новые задания, оператор получает сообщение. Флаг снимается сам, когда место освободилось.
- pagefile — фиксированного размера; тяжёлые CPU-проверки — с лимитом памяти, иначе pagefile съедает диск.
- Чужие серверы и CI: свой пакет удаляется сразу после запроса, артефакты с `expire_in: 1 day`, общий потолок (у нас 300 МБ артефактов и не больше 10 пакетов) со сторожем.

Подробные правила, пример сторожа на Python и чек-лист перед запуском новой машины — в скилле storage-hygiene приватной базы знаний владельца.

## Стабильность GPU

Если в журнале System появляются `nvlddmkm` (Id 13/153) и `Display 4101 «драйвер перестал отвечать и был восстановлен»`, а обучение падает с `CUDA error: unspecified launch failure`:

1. **TDR.** По умолчанию Windows сбрасывает драйвер, если GPU не отвечает 2 с. `-SetTdr` ставит `TdrDelay=60`, `TdrDdiDelay=60` (`HKLM\SYSTEM\CurrentControlSet\Control\GraphicsDrivers`) и сохраняет прежние значения в `C:\ProgramData\gpu-worker\tdr_backup.txt`; `-UndoTdr` возвращает их. Действует после перезагрузки. Это убирает ложные сбросы на долгих ядрах, но не лечит неисправное железо.
2. **Лимит мощности и частоты** (опция, особенно для заводски разогнанных карт). Не сохраняется после перезагрузки — повесьте на задачу «при старте» от SYSTEM:
   ```powershell
   nvidia-smi -pl 250          # ватты
   nvidia-smi -lgc 0,1500      # потолок частоты ядра, МГц; сброс: nvidia-smi -rgc
   nvidia-smi -lmc 0,9001      # потолок частоты памяти; сброс: nvidia-smi -rmc
   ```
3. **ОЗУ без ручного разгона** (XMP/множитель в BIOS → Auto) и тест памяти Windows (`mdsched.exe`).
4. **Перезагрузка** после изменения TDR/BIOS/драйвера; проверьте, что сбросы 4101 перестали появляться: `Get-WinEvent -FilterHashtable @{LogName='System'; Id=4101} -MaxEvents 10`.
5. **Автовход и задачи «при входе».** Раннер, которому нужна CUDA в сессии пользователя, запускается задачей Планировщика при входе (скрыто, перезапуск при сбое). Включите автовход Windows, чтобы после ночной перезагрузки раннер поднялся сам.
6. **Раннер на нестабильной карте:** чекпойнт каждые несколько минут, сбой драйвера считается отдельно от ошибок задания (пауза и повтор), зависший тренер (лог молчит) убивается и продолжается с чекпойнта, на карте никогда не две нагрузки одновременно (общая карта — только по аренде с подтверждением).
